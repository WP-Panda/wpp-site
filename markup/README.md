# Wp Panda — статичная HTML-вёрстка

Многостраничная вёрстка магазина тем и плагинов WordPress: чистый HTML + один CSS-файл +
один небольшой JS-файл. Никакого React и сборки — файлы можно править в любом редакторе.

## Запуск

Статику можно открыть и напрямую (`index.html`), но лучше из локального сервера:

```bash
python3 -m http.server 8080   # из этой папки
# затем откройте http://localhost:8080
```

Шрифты (Google Fonts) и фотографии товаров подгружаются из интернета.

## Как устроена интерактивность

JS навешивается через data-атрибуты — при правке вёрстки сохраняйте их:

- **Панели** (поиск, уведомления, мобильное меню, корзина, галерея, предпросмотр) —
  `data-panel="имя"`. По умолчанию скрыты правилом `[data-panel]{display:none}` в конце
  `style.css`; класс `.open` показывает панель. Кнопки: `[aria-label="Поиск"]`,
  `[aria-label="Уведомления"]`, `[aria-label="Меню"]`, `[aria-label="Открыть корзину"]`.
- **Корзина** — состояние в `localStorage` (ключ `wpp-cart`), поэтому выбор переживает
  перезагрузку. `data-add="12"` — добавить товар, `data-remove` — убрать, `data-sum` —
  итоги (обновляются на корзине и чекауте). Внизу каждой страницы лежат скрытые шаблоны
  строк корзины для всех 16 товаров (`[data-row-tpl]`) — JS клонирует их при добавлении.
- **Аккордеоны** — `data-acc-btn` (кнопка) + `data-acc-body` (содержимое): FAQ и сайдбар
  базы знаний.
- **Табы товара** — `data-tab="details"` на кнопке и `data-tabpanel="details"` на панели.
- **Галерея** — `data-open-gallery`/`data-open-preview`; слайды лежат все внутри модалки
  (`[data-slide]`), JS переключает их и счётчик.
- **Выбор лицензии** (1 сайт / 5 сайтов) — обычные radio `name="product-license-*"`;
  JS пересчитывает цену (`data-price`, `data-oldprice`, `data-discount`).

## Перелинковка

Внутренняя связка страниц выстроена так, чтобы у каждой страницы были входящие ссылки:

- **Товар ↔ статьи**: на страницах товаров с публикациями — блок «Статьи о …» со
  ссылками на посты; в каждой статье блога есть карточка упомянутого продукта
  (кнопка «Подробнее») и тематический блок «Читайте также» (совпадение рубрики/продукта).
- **База знаний**: индекс `kb.html` ссылается на статьи (карточки категорий, «Популярные
  статьи», быстрые чипсы, «Документация продуктов»); в статьях — «Связанные статьи»,
  сайдбар разделов и переход «Следующая статья».
- **Карточки**: заголовки карточек товаров и постов (`<h3>`) — настоящие ссылки.
- **Футер** (на всех страницах): колонки ссылок, «Форма поддержки», «Карта сайта».
- **Служебные**: тикеты в кабинете, иконка поддержки в шапке, кнопки корзины —
  тоже ссылки.

Все навигационные кнопки конвертированы в `<a href>`; страниц-сирот нет
(проверка генератора печатает число внутренних ссылок и сирот после сборки).

## Что не «оживлено» (осознанно)

Это вёрстка, а не магазин: отправка форм, оплата, фильтры каталога, поиск по тексту,
промокоды и загрузка файлов — статичны. Кнопки без навигации ничего не делают.

## Как обновить вёрстку после изменения React-исходников

В корне репозитория:

```bash
npm run prerender
```

Генератор (`scripts/prerender/`) отрендерит каждую страницу приложения в HTML и заново
расставит data-атрибуты.
