# Wp Panda — тема WordPress

Полная пересборка темы по статической вёрстке из `../html-layout/`. Магазин работает на плагине **WooCommerce**: тема переопределяет только вывод (шаблоны) и добавляет сущности поверх (лицензионные ключи, тикеты, избранное), не трогая логику заказов, оплаты и вариаций.

## 1. Требования

| Компонент | Минимум | Комментарий |
|---|---|---|
| WordPress | 6.2 | Тема использует современные API (`wp_get_attachment_image`, CPT, эндпоинты) |
| PHP | 7.4 | Весь код проверен `php -l` |
| WooCommerce | 8.x | Обязателен: каталог, корзина, чекаут, вариации |
| Расширения PHP | стандартные | `json`, `mbstring` |

Тема **не** использует блоки WooCommerce Cart/Checkout Blocks — только классические шорткоды `[woocommerce_cart]`, `[woocommerce_checkout]`, `[woocommerce_my_account]` (их создают сами страницы при установке WooCommerce).

## 2. Установка и первый запуск

1. Скопируйте папку темы в `wp-content/themes/wp-panda/`.
2. Установите и активируйте плагин **WooCommerce** (страницы «Корзина», «Оформление заказа», «Личный кабинет», «Магазин» он создаст сам).
3. Активируйте тему «Wp Panda».
4. При активации (`after_switch_theme`) тема:
   - регистрирует эндпоинты кабинета и сбрасывает постоянные ссылки;
   - автоматически импортирует демо-контент, **если магазин пуст** (нет ни одного опубликованного товара) и импорт ещё не выполнялся.
5. Ручной импорт/доимпорт: **Консоль → Инструменты → Демо Wp Panda**.
6. Проверьте настройки ЧПУ: тема выставляет `/%postname%/` при импорте; при необходимости переопределите в «Настройки → Постоянные ссылки».

Стиль темы объявлен в `style.css` (заголовок темы), но сам визуальный слой — это `assets/css/layout.css` (полная сборка вёрстки + адаптация).

## 3. Демо-импортёр

Код: `inc/demo-content.php`. Данные: `assets/demo/demo-content.json` + `assets/demo/card-art.json` + `assets/demo/mini-art.json` + картинки `assets/demo/products/*.jpg`, `assets/demo/articles/*.jpg`.

### Что создаётся

| Сущность | Кол-во | Детали |
|---|---|---|
| Товары (темы) | 8 | тип `variable`, атрибут «Количество сайтов», вариации «1 сайт»/«5 сайтов» с разными ценами |
| Товары (плагины) | 8 | тип `simple`, лицензия «Навсегда» |
| Бандл «All Access» | 1 | простой товар, цена 29 990 ₽ (зачёркнуто 99 900 ₽), для баннера на главной |
| Статьи блога | 12 | обложки, рубрики, автор, время чтения, счётчик просмотров |
| Страницы БЗ | 21 + родительская «База знаний» | рубрики БЗ, время чтения |
| Страница «Частые вопросы» | 1 | шаблон `page-faq.php`, вопросы читаются из JSON |
| Страница «UI-кит» | 1 | шаблон `page-ui-kit.php` |
| Главная/Блог | 2 | статическая главная (`front-page.php`) + страница «Блог» как индекс записей |
| Меню «Главное меню» | 1 | Каталог, Блог, База знаний, FAQ; назначается в локацию `primary` |

### Настройки, которые выставляет импортёр

- `blogname` = «Wp Panda», `blogdescription` = «Темы и плагины для WordPress»;
- `permalink_structure` = `/%postname%/`; `posts_per_page` = 9; комментарии открыты;
- WooCommerce: валюта `RUB`, символ справа с пробелом, разделитель тысяч — пробел, десятичный — запятая, 0 знаков, отзывы включены;
- при отсутствии — досоздаёт страницы магазина/корзины/чекаута/кабинета и их опции `woocommerce_*_page_id`;
- `flush_rewrite_rules()` в конце.

### Метаданные товаров (ключ → назначение)

| Мета | Назначение |
|---|---|
| `_wpp_demo_key` | ключ демо-записи (`product:aurora`), по нему работает `wpp_demo_find_post_id()` |
| `_wpp_version`, `_wpp_wp`, `_wpp_php`, `_wpp_compatibility` | строки в блоке «Информация о товаре» |
| `_wpp_updated` | «Обновлено …» в блоке информации |
| `_wpp_card_art` | HTML-арт карточки из вёрстки (рендерится как есть, через разрешённый `wp_kses`) |
| `_wpp_mini_art` | JSON `{bg, inner}` для маленьких плиток (поиск, корзина, кабинет) |
| `_wpp_featured_order` | порядок в подборке на главной |
| `_wpp_license` | подпись лицензии («1 сайт / 5 сайтов» / «Навсегда») |
| `_wpp_changelog` | массив записей для табу «История версий» |
| `_wpp_sales` | служебный счётчик (карточки читают `total_sales`) |
| `total_sales` | счётчик продаж для карточек и сортировки по популярности |

У постов: `_wpp_demo_author`, `_wpp_demo_read_time`, `_wpp_views_label`, `_wpp_demo_featured_order`.
У страниц БЗ: `_wpp_kb_category`, `_wpp_demo_read_time`.

### Повторный импорт

Импортёр идемпотентен: существующие записи (по `_wpp_demo_key`) пропускаются, при повторном запуске создаётся только недостающее. Флаг выполнения — опция `wpp_demo_imported` (удалите её, чтобы форсировать доимпорт).

## 5. Какая страница каким шаблоном рендерится

| Страница | Шаблон |
|---|---|
| Главная | `front-page.php` → части `template-parts/home/*` |
| Каталог (+ рубрики `Темы WordPress`/`Плагины WordPress`) | `woocommerce/archive-product.php` |
| Товар | `single-product.php` → `woocommerce/content-single-product.php` → части `template-parts/product/*` |
| Корзина | `woocommerce/cart/cart.php` (пустая — `cart-empty.php`) |
| Оформление | `woocommerce/checkout/form-checkout.php` |
| «Спасибо» | `woocommerce/checkout/thankyou.php` |
| Кабинет и все эндпоинты | `woocommerce/myaccount/my-account.php` → `template-parts/account/*` |
| Блог | `home.php` |
| Статья | `single.php` |
| Архивы/теги | `archive.php`; поиск — `search.php` |
| База знаний (индекс) | `page-kb.php`; статья БЗ — `page.php` → `template-parts/kb/article.php` |
| FAQ | `page-faq.php` (вопросы из JSON темы) |
| UI-кит | `page-ui-kit.php` |
| Прочие страницы | `page.php` (заголовок + контент) |

Шапка и подвал: `header.php`/`footer.php`. Для страниц корзины/чекаута/«Спасибо» (`wpp_is_checkout_flow()`) рендерится «тонкая» шапка и короткий футер — как в вёрстке чекаута.

## 6. Интеграция с WooCommerce

### Что остаётся нативным (не трогается)

- корзина, сессии, купоны, налоги, заказы, статусы, письма;
- обработка добавления в корзину (и простых товаров через `add_to_cart.js`, и вариаций через `WC_Form_Handler` / `wc-add-to-cart-variation.js`);
- сохранение полей чекаута и аккаунта (штатные хендлеры `save_account_details`, `edit_address`, `save_address`);
- платёжные шлюзы.

### Что переопределено темой

- шаблоны каталога, карточки, мини-корзины, корзины, чекаута, «Спасибо», кабинета (см. раздел 4);
- **стили** самого WooCommerce отключены (`woocommerce_enqueue_styles → []`), скрипты остаются;
- поля чекаута фильтруются (`woocommerce_checkout_fields`): убраны адрес/индекс/штат и доставка, добавлен ИНН, переставлены приоритеты и подписи;
- сортировка каталога: значения макета (`popular`, `rating`, `price-asc`, `price-desc`) маппятся на `orderby` WC через `woocommerce_get_catalog_ordering_args`;
- мини-корзина обновляется своим AJAX (`wpp_mini_cart`) и фрагментами `wc-cart-fragments`.

### Хуки, которые добавляет тема

| Хук | Действие |
|---|---|
| `woocommerce_order_status_completed` / `…_processing` | генерация лицензионных ключей (`inc/account.php`) |
| `woocommerce_checkout_fields` | кастомизация полей чекаута |
| `woocommerce_checkout_update_order_meta` | сохранение `домен для активации`, «откуда узнали», ИНН |
| `woocommerce_get_query_vars` | эндпоинты `licenses`, `support`, `new-ticket`, `wishlist` |
| `woocommerce_login_redirect` / `registration_redirect` | редирект в кабинет |
| `template_redirect` | приём формы нового тикета; сохранение ИНН; обработка приватности |

## 7. Оформление заказа

Форма чекаута (`form-checkout.php`) рендерит поля штатной функцией `woocommerce_form_field()` в карточках макета, поэтому валидация и сохранение — полностью стоковые.

| Карточка | Поля |
|---|---|
| 1. Контактные данные | `billing_first_name`, `billing_last_name`, `billing_email`, `billing_phone` (не обязателен) |
| 2. Платёжные данные | `billing_country`, `billing_city`, `billing_company`, `billing_inn` (кастомное, не обязателен) |
| 3. Дополнительно | `домен для активации` → мета заказа `_wpp_activation_domain`, «откуда узнали» → `_wpp_source`, комментарий к заказу |

Список способов оплаты и кнопка подтверждения выводятся штатным блоком `woocommerce_checkout_order_review` (таблица обзора скрыта в CSS — её заменяет панель «Ваш заказ»). Кнопка в панели итогов (`Перейти к оплате`) кликает по штатной `#place_order`.

Итоги (`Подытог`, скидка купона, «НДС не облагается», Итого) считаются живой корзиной `WC()->cart`.

## 8. Личный кабинет

Каркас: `woocommerce/myaccount/my-account.php` — шапка страницы (заголовок раздела + карточка пользователя), липкое боковое меню с иконками и счётчиками, тёмная карточка «Нужна помощь?», контент раздела.

| Раздел | Эндпоинт | Источник данных |
|---|---|---|
| Панель управления | `…/личный-кабинет/` | приветствие, 4 счётчика, последние заказы, быстрые ключи |
| Заказы | `…/заказы/` | `wc_get_orders`; табы Все/Выполненные/В обработке/Возвраты (серверный фильтр `?status=`), живой поиск строк |
| Просмотр заказа | `…/заказы/123/` | штатный вывод `view-order` в карточке темы |
| Загрузки | `…/загрузки/` | `wc_get_customer_available_downloads` + товары по `_wpp_demo_key` |
| Лицензии и ключи | `…/лицензии/` | мета заказов `_wpp_license_keys` (см. раздел 9) |
| Поддержка | `…/поддержка/` | тикеты `wpp_support_ticket`; просмотр переписки `?ticket=ID` |
| Новый тикет | `…/новый-тикет/` | форма (продукт из покупок, тема обращения, заголовок, сообщение), защита нонсом |
| Избранное | `…/избранное/` | карточки каталога из списка избранного |
| Платёжный адрес | `…/платёжный-адрес/` | своя разметка, сохранение штатным `edit_address` |
| Способы оплаты | `…/способы-оплаты/` | токены `wc_get_customer_saved_methods_list` |
| Данные аккаунта | `…/данные-аккаунта/` | своя разметка, сохранение штатным `save_account_details` |
| Выйти | `…/выйти/` | штатный логаут |

Тикеты: тип записи `wpp_support_ticket` (`private`), меты `_wpp_ticket_product`, `_wpp_ticket_status` (`open`/`closed`), переписка — комментариями к тикету. Ответ клиента добавляется формой с нонсом; у поддержки — полноценная админ-система (`inc/tickets-admin.php`):

- **Меню «Тикеты поддержки»** (иконка «спасательный круг») в консоли со счётчиком открытых обращений.
- **Список**: колонки Клиент (имя + e-mail), Товар, Статус (цветной бейдж), Сообщения, Активность (дата последнего сообщения); фильтр по статусу над списком.
- **Экран тикета**: метабокс «Детали тикета» — номер `#T-…`, клиент (ссылка на профиль), товар, дата, смена статуса Открыт/Закрыт; под редакционным полем — подсказка, что это первое сообщение клиента.
- **Метабокс «Ответ клиенту»**: текстарея + кнопки; ответ сохраняется комментарием от имени администратора и сразу виден клиенту в «Поддержке» (в шаблоне помечается золотым кольцом), клиенту уходит письмо (можно отключить чекбоксом), чекбокс «закрыть тикет после отправки» (работает и с пустым текстом — можно просто закрыть без ответа); текстовый ответ в закрытый тикет открывает его заново. Внизу блока — последние 5 сообщений переписки.
- **Индикация новых событий**: когда клиент создаёт тикет, отвечает в нём или закрывает его, тикет помечается метой `_wpp_ticket_unread`; в списке в колонке «Сообщения» появляется красная точка «новое». Метка снимается, когда админ открывает тикет на редактирование или отвечает в нём.
- Счётчик в админ-меню учитывает **только открытые** тикеты (статус берётся так же, как в колонке «Статус», включая тикеты без меты).
- Клиент может сам закрыть свой тикет (и открыть заново) кнопкой в шапке переписки в ЛК.
- **Уведомления**: о новом тикете письмо уходит на `Администратор → E-mail` (Настройки → Общие), ответ поддержки письмуется автору тикета.

**Уведомления в кабинете (колокольчик в шапке)** — `inc/notifications.php`:

- Ответ поддержки в тикете создаёт уведомление в мете пользователя `_wpp_notifications` (список до 20 шт., новые сверху: заголовок, отрывок ответа, «сколько назад», ссылка на переписку `?ticket=ID`).
- Колокольчик показывает красную точку-бейдж только пока есть уведомления; счётчик дублируется в шапке панели.
- В панели кнопка **«Очистить уведомления»** (AJAX `wpp_clear_notifications`): удаляет список полностью — даже непрочитанные, бейдж исчезает. Панель остаётся пустой, пока не придёт новое событие (новый ответ создаст новое уведомление, старые не вернутся).
- Для гостей и при пустом списке — заглушка «Пока без уведомлений».

## 9. Лицензионные ключи

- Генерация: при переходе заказа в статус **Выполнен** или **В обработке**, один ключ на позицию (для вариаций — с учётом `variation_id`), повторная генерация для той же позиции не создаёт дубль.
- Формат ключа: `WPP-XXXX-XXXX-XXXX` (три группы по 4 знака, алфавит без похожих символов).
- Хранилище: мета заказа `_wpp_license_keys` — массив `{product_id, variation_id, key, tier, sites[], created}`.
- Вывод: страница «Спасибо» (ключ + копирование + скачивание), кабинет «Лицензии и ключи» (карточка продукта, тариф, статус «Активна», маска ключа `WPP-••••-…`, кнопки показать/копировать, прогресс слотов `1 из 5`), блок «Быстрый доступ к ключам» на панели управления.
- Привязка к сайтам (`Отвязать`) — интерфейсные заготовки: массив `sites` заполняется при активации ключа внешним сервисом/плагином активации (в этой версии — пусто).

## 10. Избранное (wishlist)

- Кнопка-сердце на карточках каталога и на карточке товара (атрибут `data-wpp-wishlist="<ID>"`), переключение по AJAX с обновлением всех кнопок того же товара.
- Гости: массив в `$_SESSION['_wpp_wishlist']` (старт сессии на `init`, приоритет 1).
- Авторизованные: мета пользователя `_wpp_wishlist`.
- При входе гостевой список объединяется со списком пользователя (`wp_login`).
- Счётчик — в боковом меню кабинета; раздел «Избранное» рендерит живые карточки `content-product.php`.

## 11. AJAX-контракт

Все экшены идут в `admin-ajax.php` (адрес в `wppTheme.ajaxUrl`).

| Экшен | Нонс | Параметры | Ответ |
|---|---|---|---|
| `wpp_search` | `wpp-search` (`searchNonce`) | `q` | `{rows: HTML, count}` — до 6 товаров |
| `wpp_mini_cart` | `wpp-cart` (`cartNonce`) | — | `{html, count, subtitle, total}` |
| `wpp_cart_remove` | `wpp-cart` | `key` | `{success}` |
| `wpp_cart_variation` | `wpp-cart` | `key`, `variation` (ID вариации) | `{success}` — замена позиции на другой тариф |
| `wpp_apply_coupon` | `wpp-cart` | `code` | `{notice}` |
| `wpp_toggle_wishlist` | `wpp-wishlist` (`wishlistNonce`) | `product_id` | `{active, ids}` |
| `wpp_clear_notifications` | `wpp-notifications` (`notifNonce`) | — | `{count: 0}` — очистка колокольчика в шапке |
| `wpp_subscribe` | — | `email` | `{message}` — рассылка хранится в опции `wpp_subscribers` |

Служебные экшены темы не используются для изменения данных без нонса, кроме публичной подписки (только валидный email, дедупликация).

## 14. Особенности и ограничения

1. **Способ оплаты для теста.** По умолчанию в свежей установке доступен «Оплата наличными» — включите любой шлюз, ключи выдаются при статусах «В обработке»/«Выполнен».
2. **Привязка ключей к доменам** («Отвязать», счётчики слотов) — интерфейсные заготовки: реестр активаций предполагается внешним (сервис активации), массив `sites` в мете ключа пока пуст.
3. **Скачивание файлов** ведёт на файл загрузки товара (поле «Загрузки» → «Файл для скачивания» у товара); демо-товары создаются как виртуальные/загружаемые без приложенного архива — приложите свои `.zip`.
4. **Рассылка** (`wpp_subscribe`) хранит адреса в опции `wpp_subscribers`; интеграция с внешним сервисом отправки — на стороне проекта.
5. **Счётчики просмотров постов** (`_wpp_views_label`) — статичные строки из импорта; подсчёт реальных просмотров не ведётся.
6. **Вёрстка — источник правды.** `html-layout/` не меняется; любые правки темы сверяются с ней. Стили темы — это собранная таблица вёрстки, поэтому в теме нет сборщика: правки вносятся в секцию адаптации `layout.css` или в шаблоны готовыми классами.
